# 性能优化 TODO 与验收

本轮以本地源码编译的 Hubble + PD + hstore Server 为准，保持现有同步/异步入口，不引入新结果服务。任务采用独立 worktree 实现，集成后复测。所有耗时收益以同协议的新基线对比为准。

- [x] 建立查询后端、查询前端、空间/图列表三个独立 worktree，安排独立代码审查。

## 用户补充：大属性可视化预览

- [x] `preview:true` 字符串最多 256 字符并注明原始长度；大二进制值只返回大小说明；超长 Map 键整项省略并明确标记；集合最多 20 项、深度最多 4 层，每次查询共享10,000个属性/通用值投影预算（不是总字节上限）。实际点边标识、数值精度、路径顺序保持不变。
- [x] JSON/Table/Graph 使用脱离 SDK 数据对象的预览副本，禁止意外触发属性写入；未启用 preview 的属性返回保持兼容，存储原值不变。
- [x] 截断预览只读，导出/本地适配器重新载入保留标记；实际数据库导入接口明确拒绝预览文件。仓库没有服务端保存画布功能；普通完整属性仍可编辑。
- [x] 真实 100 KiB / 1 MiB 文本属性与 256/257 字符边界、长 ID/BigInt 的响应大小、原值校验和 Chrome 交互验证；二进制预览由单元测试覆盖，没有声称真实二进制 API/Chrome 夹具验证。

- [x] **最终 Review 补测**：聚合后展开、Map 键过滤、边 sentinel、Cypher 分组大 LIMIT 预检及查询错误消息2048字符上限；后端查询/投影55项、异常/历史19项分组回归，最终mapper小修20项重叠定向回归；局部归约/显式界限5项真实 API、原值完整性复核及6项采样脚本负向测试通过。

## 最终交叉审查与统计收敛

- [x] 查询默认上限/预览共享解析规则；图构造前完成投影，已有预览属性不重复扣预算。1000顶点×10属性同一测试在移除跳过逻辑后失败、恢复后通过，未跳过测试。
- [x] 图/空间核心信息不等待统计或Schema；默认读取缓存/已有快照，没有快照时显示未统计，不执行点边扫描。
- [x] 显式统计使用每类最多100000个点/边的`groupCount().by(label)`，提示可能近似；按实际Server、授权身份、空间和图隔离30分钟缓存，不将不同连接/身份的结果混用；复用Guava，最多1024项并在写入30分钟后过期，实际清理和容量驱逐已测，既有异步任务map保持独立。
- [x] 只读保护按元素生效：只有属性被裁剪的点/边只读，完整元素仍可编辑；SDK元素ID与预览元数据在真实JSON中均为字符串。混合2点夹具实际Chrome确认完整点Edit可用、部分点Edit禁用、无PUT/PATCH，原值SHA不变。
- [x] 最终后端集成186项、前端同组合18组/401项及生产构建通过；查询8项API、属性原值、统计7次调用、统计等待时导航可用和默认300/切图真实检查通过。详见[最终验证补充](VALIDATION.md#最终交叉审查与按需统计补充)，不改写历史性能样本。
